# LOG-8.4A — Hotel directory and onboarding

Dedicated platform operators can list/search paginated properties and create a new Philippine property with a new admin account in one transaction. Existing hotel accounts are never attached or modified. Duplicate admin emails reject onboarding; distinct properties may share a name. The initial password must be replaced before operations; the operator must securely communicate the initial password to the new admin. No automatic email or invitation is sent. The account is active immediately, no billing or trial is created. Room inventory and business date/operational configuration still require normal hotel setup. The operator receives no property membership. Directory returns only property metadata and aggregate active membership/room counts, not guest records, staff contact information, or hotel finances. Security logging records approved IDs only, best effort (not a durable commercial audit). No new migrations or env variables. Existing CLI hotel creation remains available. No subscription enforcement, suspension, plan limits or MRR in this increment. Test only synthetic records in CI; no live customer creation during development.
