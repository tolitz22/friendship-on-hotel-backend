# LOG-8.4E — Manual hotel access lifecycle

Deploy migration first. All existing hotels default active. Only dedicated platform admins can transition a hotel with a reason, explicit confirmation and current revision; durable audit records retained. Restricted blocks new booking, group booking/hold creation including hold conversion. Existing reservations (including check-in/out, extensions, cancellation), financial operations and staff management continue. Suspended requires prior restriction, no nonterminal/unknown reservation states, active holds or unreconciled shifts, and operator confirmation that financial obligations, guest service, ongoing work and integrations have been cleared. This is not a complete financial-integrity scan. Suspended blocks new non-read HTTP requests in the hotel membership route group; authorized existing reads remain available, subject to original roles. Password/login, platform operations and other properties remain unchanged. Public invitation acceptance checks suspension; critical booking, stay and cashier-open paths recheck under hotel lock. Other in-flight requests may finish; schedule suspension during a controlled quiet window. External finance webhooks, worker jobs, previously authorized realtime channels and privileged CLI/direct DB operations are not disabled by this HTTP access policy. GET endpoints may have incidental internal side effects. No automatic suspension on expiry, deletion, global account disable, token revocation, or guaranteed infrastructure-wide read-only mode. Reactivation is manual and does not change subscription status. If financial cleanup is needed, reactivate/restrict and resolve through normal workflows. No new env vars. Tests use synthetic data only.
