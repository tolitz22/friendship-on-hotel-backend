# LOG-8.3.1 — Monitoring performance

Events and metrics each allow 20 requests/minute per authenticated user, with authorization and validation before cache access. Successful responses are cached for 30 seconds using the configured Laravel cache store; no raw provider logs or credentials stored. Cache identity includes normalized filters and a digest of the connection configuration. 16 fixed slots per endpoint cap cache keys (collisions cause fresh reads, never cross-filter results). Cache lock prevents concurrent fills of a slot when the store supports locks; contention returns 429 with Retry-After 3. Cache outage falls back to a fresh bounded query. File/array cache is instance-local; no cross-replica guarantee. Failed, partial and not-configured results are not cached. Original observedAt is retained. Retry-After is exposed to frontend CORS. Health and worker endpoints retain six/minute. Monitoring-related 429 events retain safe fixed route metadata; existing logs stay unchanged. No global log suppression, no security rate-limit removal. Aggregate metrics continue to include monitoring requests and warnings; recent event filters distinguish monitoring from other events. No migrations or required new environment variables.
