# LOG-8.2 — Infrastructure health

GET /api/v1/platform/health is authenticated, dedicated platform-admin only, no-store, rate limited to 6 requests/min per user. It probes the current API instance, database SELECT 1, PostgreSQL logical database bytes (not Railway volume capacity; unsupported for MySQL/SQLite), configured cache using a unique 30-second key with cleanup, and Grafana read connection with a fixed last-minute query limit 1. No hotel records are modified and no raw logs or credentials are returned. Thresholds are initial operator defaults: DB/cache >500ms and Grafana >2000ms degraded; array cache is process-local and degraded by design. File cache is marked local. A failed size query does not imply database downtime. The backend being reachable is a point-in-time observation, not uptime; if auth/database is unavailable before the route is reached the browser cannot isolate the failure. No public deep-health endpoint, no independent background collector. Browser history is session-local only and bounded; no persistent availability history until later infrastructure monitoring. Railway commit SHA is exposed only if valid; optional PMS_DEPLOYMENT_REVISION fallback. No additional required env vars or database migrations. The Grafana request is bounded to 5s; DB/cache timeouts depend on configured drivers. No worker heartbeat until LOG-8.3.
