# LOG-8.4D — Capacity

Snapshot limits are enforced for assigned hotels, including expired agreements until replacement. Unassigned hotels and null limits are unrestricted. Optional PMS_SUBSCRIPTION_CAPACITY_ENFORCED=false switches to advisory only; default true. Rooms count every registered physical room, including blocked/out-of-service rooms. Staff count every active membership, even if the global user is inactive; invitations do not reserve seats. This avoids account-status changes bypassing the quota. Capacity checks run only for new rooms, new active memberships (including attachment and invitation acceptance), and membership reactivation; invitation issuance also checks current capacity. Hotel row locks serialize these paths with agreement changes. Bootstrap admin CLI respects limits; direct SQL/seeds remain operator-only and outside enforcement. No existing records deleted or deactivated; role changes, room edits, membership deactivation, reservations, check-in/out and financial operations remain unchanged. A plan with lower limits may be assigned; existing overages are shown and growth is blocked. 80% is near, 100% full, above 100% over. No migrations beyond prior LOG-8.4C; ensure those migrations are deployed first. Hotel admin capacity endpoint returns usage only (no prices); platform subscription list includes aggregate usage. No customer mutations for live testing.
Prior LOG-8.4C CI fixes: explicit short unique index identifier for MySQL and date-only expiry predicates for SQLite. Already-applied PostgreSQL migrations need no index rename; if an earlier MySQL migration failed partway through, inspect the partially created tables and migration state before retrying, never drop real subscription records blindly.
